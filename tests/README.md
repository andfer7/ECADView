# Testing the browser application

The Python suite covers format parsing, compact SVG metadata, physical copper
stacks, 3D geometry, offscreen font/bounds processing, retained WebGL compilation,
reference raster comparisons, isolated compiler limits, HTTP resources and
browser startup. The native Qt window/canvas tests and benchmarks were retired
with that interface. Reference raster code lives in `pcbvisualizer/geometry/`;
it validates compiler geometry and does not create viewer windows.

```sh
QT_QPA_PLATFORM=offscreen uv run --locked python -B -m unittest discover -s tests -v
```

The browser regression tests launch the real Python server and load its HTML,
CSS, and JavaScript, with small SVG fixtures in place of the Altium renderer.
They require the project's Python environment, Node.js 20 or newer, and Playwright. Install
the locked test dependencies from the project root:

```sh
npm ci
npx playwright install chromium
npm test
```

To use an installed Google Chrome instead of downloading Chromium, skip the
browser installation and add `PLAYWRIGHT_CHANNEL=chrome` to the test command.

Navigation coverage includes scroll-to-pan, Ctrl-wheel pinch zoom, native Safari
gesture event handling, cursor anchoring with SVG margins, redraw batching,
measurement label positioning, and pending gestures during tab changes.

Selection tests cover repeated clicks to deselect and reselect components and
nets in both views, including selections from searches and cross-probing.
They also check Shift selections, shared schematic graphics, remaining exact
matches across tabs, and preservation of selections during pans and measurements.

The checked-in `fixtures/kicad/demo.kicad_pcb` and `demo.kicad_sch` exercise real
KiCad parsing through the HTTP server and browser, without a KiCad installation.
They cover mixed Altium/KiCad tabs, uploads and drag-and-drop, component/net
cross-probing, wire selection, layers, zone visibility, pin captions,
millimetre measurements, board-only WebGL output, and malformed-upload recovery.
Python tests additionally verify rotated and mirrored geometry, board cutouts
and slots, sheet-local connectivity and crossings, saved zone metadata, escaped
text, source preservation, and CLI startup loading.

`fixtures/kicad/legacy.sch` checks legacy fields, mil-to-mm coordinates, wire and
power-label connectivity, missing-library placeholders, source timestamps,
sheet boxes, and clear errors for malformed or unrelated `.sch` files. KiCad 5
PCB tests retain unquoted brackets, apostrophes, semicolons and backslashes in
names. To reproduce the reported co60 pair through Chrome, set `KICAD_TEST_PCB`
and `KICAD_TEST_SCH` to their local paths; these files stay outside the repository.
Set `KICAD_SCREENSHOT_DIR` to an existing directory to save previews from that test.

Font validation, rendering, HTTP endpoints, and launch-command tests use the
project's Python environment:

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

Server tests cover the packaged frontend resources, unknown paths, initial
document loading, upload rendering and errors, and both the original script and
`python -m pcbvisualizer` launch commands. A generated schematic exercises actual
parsing and rendering without an external fixture.

Set `PCB_TEST_FILE` to the path of the affected GasWellShutoff.PcbDoc to also
exercise all three render modes and an actual browser upload through the Python
server. This optional fixture stays outside the repository. Set
`PCB_TEST_PYTHON` if the Python environment is somewhere other than `.venv`.

Set `SCH_TEST_FILE` to a local `.SchDoc` to exercise real schematic rendering,
startup loading, and browser upload. Schematic parsing is also tested with a
temporary schematic generated by the library, without an external fixture.
When both fixture variables are set, the browser test also probes the real
schematic selection into its matching PCB and back into the source sheet.
Cross-probing coverage in both directions includes renamed source components,
pin connectivity, exact name/alias fallbacks, multiple document targets, missing
and ambiguous matches, and preservation of source selections and views.
Index tests preserve authoritative source IDs, first-row metadata semantics,
pin precedence and case-sensitive reverse matching. Browser counters verify that
component probes do no net work and repeated net probes reuse connectivity.
GPU tests check that schematic visits retain the PCB buffers, a fitted probe
draws once, and closing a resident PCB releases its buffers. For a reproducible
generated cross-probing workload and timing limits, see
[browser performance notes](../docs/browser-webgl-performance.md).

Polygon visibility tests cover solid and hatched pours, preservation of custom
pad shapes and ordinary copper, selection overlays, click-through to routes,
layer controls, and per-tab visibility. Python rendering checks verify the
source polygon links against SVG IDs in full, top, and bottom views.

Net-label tests cover zoom-dependent visibility, literal net names, mirrored
pads and rotated routes, drill holes, clipping, occlusion and label collisions.
They also exercise pan/resize alignment, hidden layers and pours, tab changes,
and click-through selection and measurement.
Via coverage checks annular-ring placement around large drills, duplicate copper
across layers, mirrored geometry, small vias at closer zoom, visibility and tab
state, and selection/measurement through the captions.
Component pin tests cover numeric/alphanumeric identifiers, unconnected pads,
two-row pin/net captions, cramped-pad fallback, mirrored pads, holes, visibility,
navigation, and click-through interactions. A generated PCB verifies source pad
numbers and component links in full, top, and bottom render modes.

3D tests round-trip a generated PCB through the real parser, verify board and
body dimensions, bottom-side standoffs, curved outlines, merged drills, slots,
edge notches, and fallback notices. Browser coverage checks actual WebGL output,
camera controls and tab persistence, preservation of 2D state, lazy local assets,
unsupported browsers, and an uploaded generated PcbDoc through the real server.

CAD navigation regressions cover free top/bottom tumbling, rotation-centre and
orbit-distance stability, screen-space pan, pointer-directed wheel/pinch zoom,
surface-double-click recentering and camera restoration. Input bursts draw once
per animation frame; interrupted drags cannot resume after blur or mode changes.
Fit, F and empty-space double-click preserve viewing direction and roll while
framing geometry in wide and portrait windows; explicit presets still rotate.
Touch coverage sends real two-touch input through Chrome's DevTools protocol.
Safari gesture events are simulated in Chrome; OS touchpad input and WebKit
are not exercised by these tests.

Body editing coverage checks ray picking from both sides, board occlusion,
highlight restoration, drag suppression, Shift selections, duplicate names,
Delete/Backspace, grouped undo, tab isolation, and unchanged 2D/source geometry.
Python coverage verifies that split solids share one body identity while distinct
bodies retain separate identities even when their names match.
Highlight pixel coverage checks dark fallback bodies, black and metallic STEP
parts, and independent instances sharing geometry. It verifies exact finish
restoration, deletion/undo and highlights retained through STEP replacement and
remounting, with no extra geometry or shader compilation on selection.

STEP coverage uses the repository's authored 6 × 4 × 2 mm box fixture, embedded
in generated Altium boards and referenced by generated KiCad boards. It checks
compressed asset deduplication, authoritative body placements, bottom-side
mirroring, rotation, offset, nonuniform scale, models without extrusion outlines,
local/project path resolution and unchanged source files. Browser tests execute
the bundled OpenCascade WASM in a worker, check lazy loading and reuse, actual
STEP picking and deletion/undo, missing external model uploads, invalid-model
fallback and cancellation when leaving 3D. The runtime is served locally with
the correct WebAssembly MIME type and is included in the Python package.
Realistic board-finish tests check source-to-3D alignment, both sides' copper,
mask apertures and silkscreen, exclusion of internal copper and measurement
overlays, and independence from 2D visibility/highlighting. Browser coverage
also renders mapped materials and studio shadow maps through WebGL and checks
texture/shadow cleanup across repeated 3D mounts.
Repeated-mount coverage compares rendered pixels across twelve returns to 3D
in top, bottom and isometric views, including interrupted board-finish loads.
It checks visible copper/silkscreen and bounded GPU resource counts.
Completed-view cache tests check identical rendered pixels and zero additional
GPU uploads, shader compilation or board-texture decoding on warm tab/mode
switches. They cover deferred 2D setup, least-recently-used/byte-budget eviction,
closed tabs, context loss, STEP replacement and cancellation of incomplete loads.
Depth regressions render two contrasting faces separated by 0.005 mm, checking
that the foreground face stays solid through top/isometric views, zoom and pan.
They also check clipping coverage and verify that board finishes reuse the
original solid's faces instead of adding overlapping surface meshes.


Run `npm run test:gpu` for real Chrome/Chromium WebGL 2 compilation and pixel
coverage. It checks retained geometry reuse, highlights, holes, layer ordering,
SVG fallback, context loss/recovery, resource cleanup and mixed rectangle
selection. Rectangle tests cover both drag directions, additive selection,
hidden layers/polygons, cancellation and separate pan/measurement gestures.
Startup tests hold geometry preparation open to check the “Starting WebGL…”
message and blocked wheel/pinch, mouse and keyboard navigation. They verify
recovery after compilation failure, unavailable graphics, suspended animation
callbacks, tab changes and cancellation.
Startup selection tests enter searches while compilation is pending, verify
that hidden SVG geometry is not cloned, and check both the first WebGL frame
and SVG fallback. They count actual startup draws to catch redundant redraws.

Launcher tests require every entry point to start the local browser server by
default, preserve `--web` compatibility, `--no-open`, browser choice and startup
files, and dispatch frozen geometry workers without starting another server.
Quit tests verify the viewer-only shutdown request, stopped page and error recovery.
Packaged smoke validation must also exercise the bundled offscreen worker and
Quit viewer, checking that the backend process exits. Build and smoke-test on
each target OS; a macOS build does not validate Windows/Linux packaging.


The browser lifetime suite starts a separate backend per case. It checks actual
last-tab and whole-browser closure, refreshes, replacement viewers during the
3-second reconnect grace, multiple viewer pages, a renderer with blocked JS,
pagehide/pageshow restoration, and closure when pagehide handlers are suppressed.
Python tests exercise connection races, real stream disconnects, request-origin
validation, explicit shutdown and cancellation/reaping of an active compiler.
The shared regression-server harness holds one viewer open between cases.
